# UOM 网络式运行识别报送

本文面向厂家集成、交付和验收，描述本分支已经实现的网络式飞行数据报送。
报文参考《民用无人驾驶航空器运行识别信息报送对接说明 V2.3》，以实际代码、配套飞控能力和平台联调结果共同确定交付范围。
本功能与 [B950 实名登记和激活](uom_b950.md) 分开配置、分开保存凭据和记录；实名核验或激活成功不代表飞行报送已获平台确认。

QGC 打开后，应用级报送服务自动运行。RID 管理页面的“UOM 飞行报送”面板分别显示本地准备、网络报送、广播自检、机型、待发和留存记录。
切换页面或当前飞机不会停止其他飞机已入库记录的后台处理。当前版本在 Linux 上使用系统 Secret Service 保存报送凭据。

## 状态、飞控版本与架次

“本地准备就绪”要求身份与设备激活有效、厂家型号与飞机 SN 绑定匹配、RID 广播自检通过、有效且新鲜的遥测、已确认的固定遥控站位置、可读取的系统凭据、可写数据库及后台调度线程。
平台尚未 ACK、网络超时或平台业务拒绝不替代这些检查，也不单独取消 v2 本地准备状态。
“网络已确认”必须来自当前飞机、当前连接、当前架次近期数据的真实成功回执；旧连接、上一架次或历史补传的回执不能恢复当前绿色状态。
HTTP 200 还须有合法 JSON 和业务 `code=200`；非 200、业务失败、无效 JSON、超大响应、TLS 错误和超时均不算成功。

| 配套组合 | 实际行为 |
| --- | --- |
| v2 QGC + 配套 v2 PX4 | 明确协商身份响应版本及 `LOCAL_READINESS_V2`、`FLIGHT_CONTEXT` 能力；解锁使用本地准备，平台状态单独显示。 |
| v2 QGC + 仅支持 v1 的飞控 | 可识别旧版本并提示升级；不能靠猜测能力或虚构 ACK 启用 v2。旧固件的 ACK 解锁语义保留。 |
| 旧 QGC + v2 PX4 | v1 请求仍采用 v1 状态语义，不把旧报文中的空扩展字段解释成本地就绪。 |
| 未协商、身份失效、错 session/boot、重放序号 | 拒绝作为当前就绪或飞行上下文。 |
| SITL、HIL、日志回放、MockLink | 不允许进入正式/官方联调报送；只在明确隔离的测试配置内验证。 |

配套 PX4 每秒 5 次发布 `AMOV_UOM_FLIGHT_STATUS`，包含飞控启动标识、连接 session、当前架次序号、真实起飞 UTC、单调发送时间及状态标志：

| 标志 | 值 | 含义 |
| --- | --- | --- |
| `ACTIVE` | 1 | 已真实起飞、尚未确认落地。 |
| `AIRBORNE` | 2 | 可信落地检测认为当前在空中。 |
| `TAKEOFF_UTC_VALID` | 4 | 起飞瞬间已有有效、新鲜 GNSS UTC，已锁存起飞 UTC。 |
| `BROADCAST_READY` | 8 | 绑定 RID 身份有效且独立 DroneCAN 广播自检新鲜、成功；不包含 UOM 准备判定。 |
| `SIMULATION` | 16 | PX4 SITL 来源；无此标志也不能代替厂家型号和 SN 白名单校验。 |

每次已解锁的“确认落地→离地”递增架次；再次起飞即使未重新解锁，也会生成新架次。
确认落地后保留该架次序号和起飞 UTC，便于收尾和重连核对。
QGC 重连、切换页面或跨午夜不改变已有架次的 `orderId`。
`orderId` 使用真实起飞日期（UTC+8）与持久化随机后缀，格式为 `yyyyMMdd-XXXXXXXX`。
飞控启动标识、架次、身份快照、厂家账户和型号共同限定复用范围。
起飞时 UTC 未知则该架次始终未知，不用解锁时间、QGC 连接时间、当前系统时间或后来的 GNSS 授时追补。

v2 PX4 接受状态心跳和样本年龄的窗口为 3 秒，QGC 报送侧对组合遥测和飞行上下文采用更严格的小于 1 秒新鲜度检查。
v2 解锁后，待运行以及首次实际发送后的确认宽限期不因缺少 ACK 告警；QGC 从实际发送开始计时，失败状态或已确认后 ACK 超过 5 秒失效才触发网络告警。本地准备失效仍立即告警，不自动改飞行模式；独立的其他飞控安全检查仍生效。
产品解锁检查需交付固件正确配置 `COM_RID_UOM`。QGC 不自动关闭它，也不修改 `COM_ARM_ODID` 绕过自检。

## 字段 001–021 的实现映射

当前在已解锁期间每 500 ms 采样一次，解除武装时另做一次收尾；未解锁静置阶段只检查准备状态。采样使用已有 MAVLink 遥测快照，向飞控请求 `GPS_RAW_INT` 和 `GLOBAL_POSITION_INT` 为 5 Hz。
下表区分“编码器支持的未知值”和“当前正式采样的有效性要求”；支持未知编码不代表关键身份、位置或时间缺失时仍允许实时发送。
数值均按小端序编码；经纬度使用有符号整数。位置值 0、速度 0、椭球高度 0 均可以是真实有效值，不能当作通用未知标记。

| 编号 | 字段 | 当前实际来源与源时间 | 单位、基准与编码 | 未知或当前限制 |
| --- | --- | --- | --- | --- |
| 001 | 唯一产品识别码 | 经身份摘要核验的 `AMOV_RID_IDENTITY.uas_id`，绑定 RID boot、revision、hash | 20 字节 ASCII；通用编码器可对较短旧码左补零 | 当前飞机接入要求恰好 20 字符，不从机型名称拼接，不用临时占位码发送。 |
| 002 | 实名登记标志 | 当前身份的完整 `registration_id` 末 8 位；与身份中广播后缀一致性校验 | 8 字节 ASCII | 完整登记标志未知时写 8 个零字节；不将登记接口的任意文本当作完整标志。 |
| 003 | 系统运行类别 | 厂家绑定配置 `operationCategory`，不是实时飞行模式 | 1 字节；0 未报告、1 开放类、2 特定类、3 审定类 | 配置必须显式提供 0–3；该字段在协议中可选。 |
| 004 | 航空器类型 | RID 身份 `aircraft_class` 与厂家绑定 `aircraftClass` 必须一致 | 1 字节；0 微型、1 轻型、2 小型、3 中型、4 大型 | 不能根据 P600/B950 名称自行推断类别。 |
| 005 | 遥控站位置类型 | 当前只支持人工确认的固定遥控站位置 | 1 字节，当前写 1“遥控站位置” | 不把电脑 IP 定位或未确认手机位置冒充遥控站位置；未提供移动站正式支持。 |
| 006 | 遥控站经纬度 | Remote ID 设置中的固定经度、纬度及现场确认 | WGS84 度；经度在前、纬度在后，各 32 位，值 × 10⁷ | 每轴未知为 `FFFFFFFF`；正式本地准备要求有效且已确认。经纬度原点可有效。 |
| 007 | 遥控站高度 | Remote ID 固定高度，操作者须确认是 WGS84 椭球高 | 米；`floor((H+1000)×2)`，分辨率 0.5 m | 未知为 0；不能直接填写海拔/正高或相对高度。修改坐标或高度会清除现场确认。 |
| 008 | 航空器经纬度 | `GLOBAL_POSITION_INT.lat/lon`，其源时标是 `time_boot_ms` | WGS84 度，MAVLink 原值 ÷ 10⁷ 后编码 | 每轴未知为 `FFFFFFFF`；只接受递增源时标，并核对与飞行上下文同源开机时间相差小于 1 秒；接收新鲜但源位置积压也会被拒绝。 |
| 009 | 航迹角 | `GPS_RAW_INT.cog`，使用该 GNSS 报文的 UTC | 真北顺时针；MAVLink 厘度 ÷ 100，报送为 `floor(度×10)`，有效 0–3599 | MAVLink `UINT16_MAX` 转为未知 `FFFF`；不是机头朝向/yaw。 |
| 010 | 地速 | `GPS_RAW_INT.vel`，使用该 GNSS 报文的 UTC | MAVLink cm/s ÷ 100 得 m/s，报送为 `floor(m/s×10)` | 未知为 `FFFF`；当前本地准备要求有有效地速。 |
| 011 | 相对起飞地高度 | 当前不提供可信起飞地基准，发送未知 | 协议为 `floor((H+9000)×2)`，0.5 m | 当前编码 0。`GLOBAL_POSITION_INT.relative_alt` 相对当前 Home，不能保证相对真实起飞地；原值仅留在 `sourceMetadata.relativeToCurrentHomeM` 作诊断。 |
| 012 | 垂直速度 | `GLOBAL_POSITION_INT.vz`，源时标 `time_boot_ms` | MAVLink NED 向下 cm/s，取负并 ÷ 100 得向上 m/s；绝对值 × 2 向下取整，最高位表示下降 | 未知为 `FF`；分辨率 0.5 m/s。下降编码不能与 `FF` 冲突。 |
| 013 | 航空器大地高度 | `GPS_RAW_INT.alt_ellipsoid`，使用该 GNSS 报文 UTC | WGS84 椭球高，MAVLink mm ÷ 1000；`floor((H+1000)×2)` | 未知为 0；正式本地准备要求来源明确。不能用 `GLOBAL_POSITION_INT.alt` 的 MSL 高度替换。配套 v2 已知生产者的零高度及 MAVLink 2 零尾截断按有效解码处理。 |
| 014 | 气压高度 | 当前没有接入以 101.325 kPa 为参考的标准气压高度 | 协议为 `floor((H+1000)×2)`，0.5 m | 当前编码 0；不以普通海拔、Home 高度或气压传感器原值冒充。该字段可选。 |
| 015 | 运行状态 | 可信飞行上下文 `AIRBORNE`、独立广播 `BROADCAST_READY` 和 `RemoteIDManager.emergencyDeclared()` | 1 地面、2 空中、3 紧急、4 广播故障、5 广播故障且紧急 | 广播故障优先编码 4/5；广播正常时紧急状态编码 3，否则依据空地状态编码 1/2。紧急声明来自当前 QGC Remote ID 状态，端到端语义仍需联调验证；地面记录先本地 held。 |
| 016 | 坐标系类型 | 当前数据链固定 WGS84 | 1 字节，写 0 | 不使用地图显示的 GCJ-02 坐标替换飞控原始位置。 |
| 017 | 水平精度等级 | 当前未建立可验证的精度分档映射 | 1 字节，写 0“未知/未达到最低分档” | 不根据 GNSS 有定位直接声明高精度；将来需核验实际误差字段和分档边界。 |
| 018 | 垂直精度等级 | 当前未建立可验证的精度分档映射 | 1 字节，写 0 | 不用高度显示的小数位代替精度。 |
| 019 | 速度精度等级 | 当前未建立可验证的精度分档映射 | 1 字节，写 0 | 不用当前速度数值推断速度精度。 |
| 020 | 时间戳 | 当前已接受的 `GPS_RAW_INT.time_usec` ÷ 1000；接受的是 UTC 而非开机时间 | Unix UTC 毫秒，48 位小端 | 编码未知为 0；正式采样要求有效 UTC。重复、倒退或异常跳变不刷新新鲜度；补传保留原源时间，不能改成补传时间。 |
| 021 | 时间戳精度等级 | 当前没有跨传感器同步精度评估 | 1 字节，写 0“未知或大于 0.5 s” | 500 ms 采样周期不等于授时精度，不能据此写等级 1。 |

所有 21 项当前均置存在标志；未知与不发送字段是两件事。
字段 011 因当前 Home 不是可信起飞基准而发送未知；014 与精度字段 017、018、019、021 也保持未知，不以其他数值替代。
编码器也支持规范允许省略的 003、011、012、014，但禁止省略必选字段、使用预留值或越界后自动截断。
经纬度 `FFFFFFFF` 是未知哨兵，因此会拒绝量化后恰好为 -1 的坐标，避免把有效值编码成未知。
完整当前报文为 78 字节二进制，HTTP body 是其 156 字节**大写十六进制 ASCII**，不是直接发送二进制。

字段 008/012 的位置速度快照与 009/010/013/020 的 GNSS 快照并非硬件同步采样。
数据库 `sample.sourceMetadata` 保留 GNSS UTC、全局位置开机时间、飞行上下文开机时间、各消息本机接收单调时间、连接 session、椭球高度可用性和未知精度说明，用于排查来源和时序。
这不等于已经证明全报文的时间戳精度；真实设备的传感器到飞控、MAVLink 到 QGC 时延和快照偏差仍需联调量测。

## 厂家配置和凭据部署

网络报送使用独立厂家配置，不能直接复用实名登记接口的 `producerId`、SM4 密钥或三个登记/激活 URL。
报送协议以 `appId` 标识账户，使用报送 `appKey` 的原始 UTF-8 字节对最终大写 ASCII body 做 HMAC-SM3，签名为小写十六进制。
请求包含 `appId`、`sign`、`source`、`orderId`、`uasModel`、`uscCode`、`platform` 请求头。
凭据只在内存和系统密钥环中使用，冻结样本、普通配置、日志和诊断导出不包含 `appKey`。

配置文件顶层为 `profiles` 数组，文件最大 64 KiB。以下是**不含密钥的结构示例**，ID、SN、类别与平台字段必须替换为厂家经核实的实际值：

```json
{
  "profiles": [
    {
      "aircraftIds": ["EXAMPLEP600000000001"],
      "aircraftClass": 1,
      "operationCategory": 1,
      "profile": {
        "schema": 1,
        "mode": "commissioning",
        "endpoint": "https://uom.receive.caacic.cn/ridData",
        "appId": "REPLACE_WITH_MANUFACTURER_APP_ID",
        "uasModel": "P600-NX-DC10-5",
        "uscCode": "REPLACE_WITH_MANUFACTURER_USC_CODE",
        "platform": "REPLACE_WITH_APPROVED_PLATFORM_VALUE",
        "credentialReference": "uom-reporting/p600-commissioning",
        "source": 1,
        "backfillValidated": false
      }
    }
  ]
}
```

| 键或模式 | 实际要求 |
| --- | --- |
| `mode` | 字符串 `isolated`、`commissioning` 或 `official`，不是数字枚举。 |
| `schema` / `source` | 数值 1；当前实现只支持无人机系统直接报送 `source=1`。 |
| `aircraftIds` | 显式 20 字符产品码白名单；整个文件内不能重复。空列表或错误绑定使配置无效。 |
| `aircraftClass` / `operationCategory` | 显式数值 0–4 / 0–3；示例中的 1 不代表所有 P600 的实际分类。 |
| `backfillValidated` | 必须显式提供布尔值，初始为 `false`；完成平台重复请求、补传时效及限流联调后才能由厂家设为 `true`。 |
| `credentialReference` | 以 `uom-reporting/` 开头的凭据引用，独立于 `uom-registration/`。引用不是密钥。 |
| `isolated` | 只允许数字回环地址上的 HTTP/HTTPS 接收端，不能指向官方域名。 |
| `commissioning` / `official` | 当前代码只允许 `https://uom.receive.caacic.cn/ridData`，要求 TLS 1.2 及以上并校验证书；两种模式分别隔离数据/账户范围。 |

厂家按以下顺序部署：

1. 在厂家接入流程取得对应型号、环境的真实报送配置，核对型号、产品码、`appId`、`uscCode`、`platform` 和 `source`。本文不提供真实凭据，不证明任何账号已获平台接入授权。
2. 在交付电脑的目标 Linux 用户下安装含 Qt SQLite、OpenSSL Crypto、libsecret 的构建，确保该用户的 D-Bus 会话及 Secret Service 密钥环已启动、解锁。不能在另一个用户或 root 的密钥环中部署后期待普通用户读取。
3. 使用厂家受控部署工具或系统密钥环界面创建报送凭据项：schema 名为 `org.mavlink.qgroundcontrol.uom`，字符串属性 `reference` 精确等于配置的 `credentialReference`，secret 值为平台给出的原始 `appKey` 文本。不要将其当十六进制解码，也不要放入 shell 命令参数、环境变量、JSON、仓库或日志。
4. 保存不含 secret 的配置文件，并由厂家部署工具在当前产品构建的 QSettings 中设置 `UomReporting/profileFile` 为其绝对路径。Linux INI 形式为 `[UomReporting]` 节下 `profileFile=/绝对路径/配置文件.json`；正式版、Daily、自定义品牌、测试构建的设置文件名可能不同，不能盲目写入另一版本的 INI。
5. 打开 RID 管理页面，点击“重新加载厂家配置”，连接授权 SN 的飞机，读取身份与激活状态。重新启动 QGC 后应仍可从密钥环读取；缺失 libsecret、密钥环锁定、凭据不存在或只有会话内存值时，本地准备保持未就绪。
6. 在 Remote ID 设置选择固定遥控站位置，核对现场 WGS84 经度、纬度和椭球高度后确认。修改任一坐标或高度会清除确认，须重新核对。
7. 使用隔离接收端完成软件故障注入，再使用授权实机和平台联调环境验收。用户界面不提供任意更改官方地址、密钥或型号的开关。

当前没有客户用的报送密钥录入向导或完整厂家自动部署程序；厂家需要在自己的受控交付流程完成上述 Secret Service 和 QSettings 配置。
更换电脑、Linux 用户或密钥环时重新部署凭据；切换厂家账号或环境不能把历史样本改写到新账户下发送。
密钥轮换必须保持原记录的厂家与型号关联，恢复暂停发送前核对账户范围。

## P600 首发和 B950 扩展

当前代码按厂家配置绑定型号，不内置“凡是 P600 都允许正式报送”的判定。
P600 首发需对实际 SN 白名单、已激活 RID、配套 v2 飞控、正确航空器类别、有效固定遥控站和报送凭据完成整机验收。
SITL 标志缺失或名称含 P600 都不能替代这些要求。

扩展到 B950 时，增加独立的厂家 `profile`、B950 `uasModel`、对应类别和授权 SN 列表，按要求部署报送凭据，再完成相同的协议与实机验收。
如平台允许多个型号共用账户，仍须分别绑定型号和实际 SN，不从登记成功结果自动创建报送权限。
原 B950 实名登记、设备激活以及运行识别广播继续按各自链路验收，不能用本功能的网络 ACK 替代。
将来增加移动遥控站、真实相对起飞高度、标准气压高度或精度等级时，先确定可信来源、缺失处理及源时间，再增加接口和回归用例。

## 本地保存、网络中断与应用关闭

后台服务属于整个 QGC 应用，在独立线程内创建网络对象、调度器和 SQLite 连接。
UI 线程按 500 ms 生成不可变采样快照，通过有界队列交给后台；网络等待和数据库写入不在飞控通信回调中阻塞。
当前每机最多 8 个在途请求、应用合计最多 32 个，响应上限 16 KiB，单次网络请求有 3 秒绝对超时。
重试退避与账户暂停不改变已保存 body、源时间、身份快照或 `orderId`。

数据库位于本构建 `AppLocalDataLocation/uom-reporting/reports.sqlite`，使用 SQLite WAL、同步落盘和只允许当前用户读写的文件权限。
已采样记录、发送状态、尝试次数、HTTP/业务结果分别保存；发送成功也不删除原始采样。
关闭或崩溃后，未确认发送结果恢复为 `uncertain`，不能当作成功。

| 情况 | 当前行为与覆盖边界 |
| --- | --- |
| 已解锁、未起飞；或已确认落地 | 保留地面记录为 `held`，不会虚构占位 `orderId` 或自动向官方发送地面数据。地面格式与发送范围仍待平台确认。 |
| 真实起飞，但起飞 UTC 或身份等不可确认 | 保留为 `held` 或记录无效原因；不创建虚假的架次日期，不以后来的值重写原记录。 |
| 网络断开，飞控遥测仍持续有效 | 继续按原采样频率落盘，网络与本地准备分开；网络恢复后是否重试历史数据受补传验证开关限制。 |
| `backfillValidated=false` | 默认只发送当前会话、架次的近期实时样本；旧记录、已尝试后结果不确定的记录保留，不自动历史补传。 |
| `backfillValidated=true` | 按原冻结报文与原时间戳补传；同账户历史发送每秒最多一条且不并发挤占，不能用补传 ACK 刷新当前网络健康。 |
| 401/403 或鉴权业务失败 | 暂停对应账户网络发送，继续保存采样，等待厂家修复凭据；不把鉴权拒绝当成本地存储故障。 |
| MAVLink 遥测中断、QGC 未运行、电脑休眠/关机 | 无法取得期间新的飞行样本。本实现不能从飞控日志或 RID 自动回补这些未采样时段，也不能保证期间的地面站网络式报送连续。 |
| 存储队列溢出、磁盘不足、数据库错误 | 明确置本地未就绪并记录缺口/告警；不静默删旧记录腾空间。现有磁盘阈值为剩余 128 MiB，触发后停止可靠缓存。 |
| 切换页面、切换当前飞机、断开一架飞机 | 后台服务仍处理已经入库且允许发送的记录；断开的飞机不能因旧 ACK 显示当前网络健康。 |
| 关闭 QGC | 提示未完成工作；关闭后没有独立系统守护进程继续采样或发送。正常退出停止网络、等待已排队存储处理并 checkpoint；下次启动恢复数据库队列。 |

保存目标是至少 120 小时、保持正常 2 Hz 采样数据，不以降采样冒充足量保存。
当前实现没有按时间或容量自动删除历史记录，包括已 ACK、拒绝和 held 记录；也没有自动“满盘清理”功能。
120 小时在 2 Hz 下每机约 864,000 条，仅 156 字节 HTTP body 就约 134.8 MB，不能据此估算数据库容量。

本地合成存储验证已生成 864,000 条样本，数据量相当于单机 120 小时、2 Hz；这不是连续运行 120 小时或官方平台验收。
使用 schema 3 的实测结果如下，查询耗时为本次环境中的中位数：

| 项目 | 本地实测 |
| --- | --- |
| 数据库文件，含样本、索引和事件 | 2,096,087,040 B，约 1.95 GiB（状态切换后未 VACUUM） |
| 平均每条样本摊销占用，含事件 | 约 2,426 B |
| 在实测库大小上增加 50% 余量 | 3,144,130,560 B，约 2.93 GiB/机/120 小时 |
| `pending` 待发查询 | 2.146 ms |
| `stats` 状态汇总 | 约 0.007 ms |
| `eventSummary` 事件汇总 | 0.016 ms |

上述 50% 是本次测量的预算示例，不是所有部署条件下的容量保证；样本元数据长度、并发飞机数、事件数量、历史积累、WAL 和备份都会影响实际占用。
交付时应按真实样本和断网比例复测，另核算长期留存、备份和低空间余量；当前实现不会在 120 小时后自动删除记录。
首次将约 1.9 GB 的旧 schema 1 数据库迁移到 schema 3，本次耗时约 97 秒；测量时虚拟机同时进行完整构建，不能据此推断固定启动时间。
迁移期间本地服务保持未就绪，不对外声称存储已可用。相同规模的 schema 3 正常重开两次测得约 3.54 秒和 22.02 秒；并行全构建时，单独 SQLite `quick_check` 曾耗时 49.88 秒，启动完整性扫描明显受磁盘负载和缓存影响。
后台初始化期间入口最多暂存 64 个采样快照，按单机 2 Hz 约为 32 秒，多机按合计采样频率缩短；超过上限会明确报告采样缺口，并在后续新样本成功落库后记录缺口事件，不能声称期间数据已完整保存。
飞行中重启且历史库很大时，这一启动时延是当前恢复限制；应在起飞前启动应用并等本地准备就绪，真实设备仍需测试大库冷启动和恢复缺口。
120 小时连续写入、掉电与低空间测试仍是交付验收项，当前合成容量验证和单元测试不等同于完成该长时间验收。
导出诊断提供版本、队列数量、健康与缺口统计，不导出凭据或完整轨迹；不是数据备份/历史清理功能。

## 外部待验证项

软件回归和固件编译不等同于完成以下事项：

- 厂家账号、型号、环境权限、`appId`/`appKey`、`uscCode`、`platform` 与实际平台要求一致，并获得真实成功回执。
- 平台对地面 held 数据的接收规则、重复报文幂等、HTTP 无响应但已入库的处理、历史补传时效和速率；确认之前保持 `backfillValidated=false`。
- 无线链路时延、UTC 稳定性、GNSS 椭球高度含义、现场遥控站坐标/椭球高和跨数据源时间偏差。
- 实机广播自检是否真实反映发射功能、解锁限制在重启/更新后的持续有效性、连续起降与不同断连时机的架次恢复。
- 120 小时全频存储容量、长时间运行、强制退出/断电、低空间和多机网络拥塞。
- 遥测链路中断或地面站关闭期间仍要求连续报送的场景，需要另行验证机载网络报送或可信机载历史取回方案；当前 QGC 后台线程不能提供这段覆盖。

# B950 客户操作指南：实名核验、QGC 激活与验收

适用对象：购买 B950 整机、使用配套 Linux 版 QGroundControl（下称 QGC）的客户。
本指南按厂家已经完成正式环境接入，并在客户安装包中内置正式接口配置与登记密钥的条件编写。
请从第 1 步开始，逐项记录结果；某一步未达到预期时，先按该步提示处理。

本指南依据 `b950-uom-direct` 的现有功能整理，核对日期为 **2026 年 11 月 6 日**。
它提供操作和验收方法，不代表当前这架飞机已经通过官方联调或整机验收。

## 开始前准备

| 准备项 | 应具备的内容 |
| --- | --- |
| 整机与软件 | B950、配套飞控及 RID 模块固件、厂家交付的 Linux 版 QGC |
| 飞机身份 | 机身铭牌或交付资料上的整机产品唯一识别码（SN）、厂家名称、型号 |
| 激活前置条件 | 本机 SN 对应有效实名登记；QGC 可查询登记状态，不提供登记办理入口 |
| 连接条件 | 电脑网络可用，能连接登记核验与激活服务；飞机与 QGC 的连接正常；飞机保持在地面、未解锁 |
| 正式接入配置 | 厂家已在配套安装包内置接口配置与登记密钥；客户无需另行部署、填写或修改 |
| 测试记录 | 使用本文末尾的空白验收表，记录版本、SN、时间和截图编号 |

本次为地面登记与激活检查，按整机手册采取地面维护措施，不操作起飞。
先连接一架飞机，确认当前操作对象。

请区分以下信息：

| 信息 | 用途 | 在哪里使用 |
| --- | --- | --- |
| 整机产品唯一识别码（SN） | 标识这一架飞机；应与铭牌、RID 读数、有效实名登记一致 | 从 QGC 读取，用于登记核验和激活 |
| RID 硬件 UID | 标识机内的 RID 模块，帮助确认所选设备 | QGC 的 RID 设备信息 |
| 实名登记状态 | 确认是否满足激活前置条件 | QGC 核验结果，不能替代整机 SN |
| 生产者 ID、凭据 | 让配套软件调用官方登记与激活接口 | 厂家维护并内置于配套安装包，客户界面不提供查看、填写或修改入口 |

**不要用 RID UID 替换整机 SN。QGC 不提供实名登记办理或官网导航。**
测试截图和验收表不记录身份证号码、密码或密钥。

## 按顺序操作

### 第 1 步：连接飞机并打开 RID 页面

**操作**

1. 打开厂家交付的 QGC，给飞机按整机手册上电并连接电脑。
2. 等待 QGC 显示当前飞机，参数读取结束；确认飞机保持未解锁。
3. 打开“载具配置（Vehicle Configuration）”，点击左侧 **RID**。
4. 也可点击飞行界面顶栏的 RID 图标，打开 **RemoteID Status（状态）**面板，再点击 **UOM 登记与 RID 管理**。
   英文按钮为 `UOM registration and RID management`。

**预期结果**：页面上方出现“UOM 实名登记与激活”，下方出现 RID 身份和参数区域及“读取 RID 设备”按钮。

**未达到预期时**：没有连接飞机时先检查连接；已连接却没有 RID 入口时，让交付人员核对 QGC 版本和配套飞控固件，不用普通参数页面代替此流程。

**记录**：QGC 版本、飞控版本、RID 版本（若已知）、连接方式、页面截图编号。

### 第 2 步：读取并核对这架飞机的身份

**操作**

1. 点击 **读取 RID 设备（Read RID devices）**，等待读取结束。
2. 若出现多个 RID 设备，按厂家提供的硬件 UID 选择正确设备。
3. 将页面上的 **产品唯一识别码（整机 SN）** 与机身铭牌、交付资料逐字核对。
4. 记录 RID 模块 UID、节点号和当前激活状态。

**预期结果**：读到非空的 20 位整机 SN、RID UID，以及明确的“已激活”或“未激活”状态；SN 与实物一致。
初次交付显示“未激活”不代表故障，后续仍需核验登记并激活。
产品型号未获取时显示“未知”，QGC 不根据 SN 推测型号；请以铭牌和厂家资料为准。
换机或断连后，QGC 清除旧的当前身份及显示结果；即使切回原飞机，也需要重新点击“读取 RID 设备”。
历史记录和待处理操作仍保留，并只关联原飞机。

**未达到预期时**：

- 显示“已连接 RID，尚未绑定整机 SN”：依据厂家交付资料点击“预置出厂身份”，核对硬件 UID 并填写整机 SN。
  航空器类别从“微型、轻型、小型、中型、大型”中选择，初始不选；请查整机铭牌、说明书或厂家资料。
  “如何确认类别”说明可帮助区分类别与多旋翼、固定翼等机型；不能凭外观或型号猜测。
  核对 UID、SN 和类别后勾选永久绑定确认，再保存。资料不完整或类别不确定时，先联系厂家确认。
  **绑定后不能修改产品码；不得为继续操作而随意填写。**
- SN 不一致：暂停后续办理，让厂家核对铭牌、交付资料和 RID，不使用其他飞机的 SN 继续办理。
- 没找到 RID、读取超时或状态“未知”：核对模块供电、连接和配套固件，恢复后再次读取。

**记录**：整机 SN、UID、节点号、读取时间、初始激活状态及截图编号。

### 第 3 步：检查厂家预置配置是否可用

**操作**

1. 查看 QGC 的 RID 页面，确认仍显示第 2 步读取的本机 SN。
2. 查看页面提示，确认没有厂家接入配置不可用的提示。
3. 确认飞机连接正常、在地面未解锁，且没有待处理操作，再进入第 4 步。

客户版本固定使用厂家预置的 B950 正式接入配置，不提供环境、生产者 ID、接口地址或密钥的配置入口。
接口配置和登记密钥已内置于厂家配套安装包，登记操作不依赖客户电脑的系统密钥环。
首次安装、更换电脑、切换用户或重新安装系统后，使用厂家配套版本即可，无需另行部署登记密钥。
本机 SN 来自 RID 读取结果，无需手工填写“预期飞机 SN”；读取不会修改设备出厂身份。

**预期结果**：无需填写任何接入信息，读取本机后可以按第 4 步执行实名核验。

**未达到预期时**：提示厂家配置不可用时联系交付人员核对配套安装包版本和内置配置；不要使用联调版或其他飞机的资料代替，也不要把密钥填入普通配置文件。
按钮不可用时按后文排错表检查连接、设备状态和待处理操作。

**记录**：本机 SN、配置是否可用、检查时间和页面提示；不记录密钥值。

### 第 4 步：在 QGC 核验实名登记

**操作**

1. 保持飞机连接、在地面且未解锁，确认第 2 步的 RID 已读取。
2. 点击 **核验实名登记（Check real-name registration）**，等待结果。
3. 查看“实名登记状态”和“实名核验时间”。

**预期结果**：实名登记状态变为 **登记正常（Registered）**，核验时间更新。
此时设备可以仍是“未激活”；本按钮只检查登记，不执行激活。

**未达到预期时**：

- “未查询到有效实名登记”：本机当前不满足激活前置条件。核对 SN 与交付资料，必要时联系厂家确认登记信息。
- “实名登记已注销”：暂不能激活；有效实名登记恢复后再核验。
- “尚未核验”、接口失败或超时：检查网络和页面提示，厂家配置异常时联系交付人员。
- 按钮不可用：按后文排错表检查设备读取、未解锁状态、SN 或待处理操作。

相同参数的请求至少间隔 **60 秒**；重启 QGC 或连续点击不能绕过限制。
可以直接进入第 5 步。激活前仍会再次核验；若触发本地请求间隔限制，页面会显示实际剩余秒数，并在满足条件时自动继续。

**记录**：登记状态、核验时间、页面提示及截图编号。

### 第 5 步：激活飞机并等待 UOM 确认

**操作**

1. 确认第 4 步结果为“登记正常”。
2. 点击 **激活飞机（Activate aircraft）**。
3. 在确认框再次核对目标 SN，确认激活。
4. 如显示“等待继续激活”，保持同一架飞机供电、连接、在地面且未解锁，等待倒计时结束；不需要再次点击。
5. 自动继续时，QGC 会重新读取 RID，核对 SN、UID、设备启动会话及身份版本，再核验登记、写入并确认激活、上报结果。

QGC 会重新读取设备、核验 UOM 登记，再保存 RID 激活状态并回读确认，最后向 UOM 上报。
此过程通过飞控连接操作 RID 模块，客户不需要把身份证信息或 UOM 登记编号手工写入飞控参数。

**预期结果**：同时满足以下三项，并出现新的激活上报时间：

| 页面项目 | 应看到的结果 | 代表什么 |
| --- | --- | --- |
| 实名登记状态 | 登记正常（Registered） | 最近一次官方实名核验通过 |
| 设备激活状态 | 已激活（Activated） | 已连接 RID 的实际激活状态 |
| 最近 UOM 确认 | 激活上报已接受（Activation report accepted） | 官方接口已确认本次激活上报 |

流程提示应为 **“RID 激活已确认，UOM 已接受激活上报”**，且没有待处理操作。
三个结果分别判断；单独出现“登记正常”或“已激活”不能记为整项通过。

**未达到预期时**：设备已激活但上报未确认时，按“待处理操作”继续；
设备写入失败、回读不一致或固件不支持时联系厂家处理。
不要把旧的上报成功时间当作本次成功。

**记录**：确认的 SN、三个状态、实名核验时间、激活上报时间、最终提示及截图编号。

### 第 6 步：断电重启飞机，检查身份和激活是否保留

**操作**

1. 确认第 5 步已结束、没有待处理操作，飞机仍在地面且未解锁。
2. 按整机手册关闭并重新接通飞机电源，不在写入过程中断电。
3. 重新连接 QGC，等待连接稳定，打开 RID 页面并点击 **读取 RID 设备**。
4. 对照第 2 步记录，检查 SN、RID UID 和设备激活状态。

**预期结果**：SN 与 UID 不变，设备激活状态仍为 **已激活**。
断连后当前身份及显示结果清空，重新连接后先读取设备；实名状态显示“尚未核验”不等于有效实名登记被撤销，按第 7 步重新核验即可。
“最近 UOM 确认”及其时间属于历史回执，单凭该历史记录不能证明本次设备读取成功。

**未达到预期时**：激活丢失、身份变化或一直读不到设备时记为失败，保留前后截图并联系厂家，
不要用再次激活来掩盖重启保持失败。

**记录**：断电重启时间、重启后的 SN、UID、激活状态和截图编号。

### 第 7 步：重启 QGC 并完成本轮验收

**操作**

1. 正常退出并重新打开 QGC，连接同一架飞机，进入 RID 页面并再次读取设备。
2. 核对重新读取的 SN 正确，厂家预置配置仍可使用，无需重新输入接入信息。
3. 与上次核验至少间隔 60 秒后，点击 **核验实名登记**。
4. 填完本文末尾的验收表，保存脱敏截图。

QGC 重启后，“实名登记状态”会回到“尚未核验”，实名核验时间清空，需要重新核验。
设备激活状态需要重新读取；读取确认同一 SN 和 UID 后，“最近 UOM 确认”及其时间可以从本机历史记录恢复。

**预期结果**：设备仍“已激活”，新的实名核验为“登记正常”，历史“激活上报已接受”及其时间能够正确对应本机；
无未完成事务。重新核验不应刷新历史激活上报时间。

**未达到预期时**：厂家配置不可用时联系交付人员；核验失败时按第 4 步处理；
历史上报缺失、状态串用或出现未完成事务时交给厂家核查，不填写“全部通过”。

**记录**：QGC 重启时间、厂家配置是否可用、新核验时间、三个状态、待处理操作是否存在及本轮结论。

## 遇到待处理操作时

断网、超时、断连或软件重启后，设备和 UOM 可能只完成了一部分步骤。
仅因本地限频暂停、尚未写入设备的本次已确认激活，可以在当前 QGC 会话内自动继续。
等待期间重复点击不会提交新操作，也不会延长原倒计时。
断线、切换飞机、身份或厂家配置变化、解锁、运行状态变化及 QGC 重启后，自动继续资格会取消。
服务器异常、写入结果不明和取消登记不适用这条自动继续规则。

看到 **继续激活（Continue activation）** 或 **继续取消登记（Continue deregistration）** 时，按下面处理：

1. 保持或恢复同一架飞机的供电和连接，飞机在地面、未解锁。
2. 点击“读取 RID 设备”，确认 SN 和 UID 仍与原记录一致。
3. 检查互联网和页面提示，等待页面要求的请求间隔；厂家配置不可用时联系交付人员，若设备写入已经确认，QGC 可只重试上报，不重复写入设备。
4. 倒计时结束后点击对应的“继续”按钮，核对目标飞机与提示内容，再确认继续。
5. 按原操作的完整预期结果检查；待处理状态消失后，才记录该操作完成。

待处理操作始终关联原飞机，换机或断连不会删除记录，也不会把操作转给另一架飞机。
厂家接入配置需要修复时联系交付人员；继续前仍需重新读取原飞机并核对登记状态。
若提示原操作为注销，继续可能再次发送注销请求；本次首次激活验收不应包含这类操作，先联系交付人员核实。

**记录**：首次失败时间、失败提示、恢复时间、重试次数、最终状态与截图编号。
没有取得设备确认和 UOM 成功回执时，保留“未完成”结论。

## 常见问题与排查

| 现象 | 处理方法 |
| --- | --- |
| 产品型号显示“未知” | 尚未获取型号；以铭牌或交付资料为准，不根据 SN 猜测 |
| 核验、激活按钮不可用 | 查看按钮上方具体原因：先读取 RID、绑定 SN、核对身份、恢复连接、保持地面未解锁或继续待处理操作 |
| 厂家配置不可用或与待处理操作不符 | 联系交付人员检查配套版本和配置，客户无需输入密钥 |
| 未查询到有效实名登记或实名登记已注销 | 当前暂不能激活；核对 SN 和登记信息，满足有效登记条件后再核验 |
| 显示等待继续激活及剩余秒数 | 保持同一飞机连接、地面未解锁，倒计时结束自动继续；不重复点击 |
| 显示继续激活或继续取消登记 | 按“遇到待处理操作时”恢复，倒计时结束后确认继续 |
| 设备写入结果不明或回读失败 | 保留提示，重新读取原 RID 并核对身份，联系厂家确认后恢复 |
| 设备已激活，UOM 尚未确认 | 检查网络及提示，继续原操作；已确认的写入不会因重试上报而重复执行 |
| 重启后实名状态尚未核验 | 读取同一 RID，再执行实名核验；不能仅因此判定登记失效 |
| 顶栏显示网络上报未就绪 | 查看下节功能边界，激活成功不代表实时飞行网络上报已实现 |

## 本轮验收的边界

本指南验收的是 **QGC 登记核验、RID 激活、UOM 激活上报和重启保持**。
民航局对“实名登记后核验激活”及转让、报废时的取消激活流程有说明，参见
[《民用无人驾驶航空器实名登记和激活要求》解读](https://www.caac.gov.cn/PHONE/XXGK_17/XXGK/ZCJD/202604/t20260421_230620.html)。

当前这版 QGC 的 **正式实时飞行网络上报尚未实现**。
“激活上报已接受”只表示激活状态得到官方确认，不表示飞行位置等实时数据已上报。
顶栏的“UOM network reporting”及“Network reporting not ready（网络上报未就绪）”涉及独立的上报功能，
不能通过修改解锁检查参数消除提示后就算通过。

页面只读取并显示现有飞控解锁检查配置，不会自动修改 `COM_ARM_ODID`、`COM_RID_UOM`。
首次未激活时限制飞行、取消激活后限制飞行、固件升级后身份与激活保持等整机项目，
由厂家按配套固件和整机验收程序单独验证。
完成本文步骤不等同于完成全部飞行条件检查或获得飞行活动批准。

**取消激活并注销登记**用于退出使用、所有权变更等办理，会改变设备状态并向 UOM 申请注销，
不属于首次使用的必测步骤。需要办理时再按厂家指引选择原因、填写说明并确认目标飞机。
该操作的原因说明上限为 200 个 UTF-8 字节，中文通常每字占 3 字节。
设备未激活确认、未激活状态上报、官方注销全部完成后，才能记录办理成功。
